# 句间停顿

商品设置中的“句间停顿”默认是自动节奏。选择“手动”后须填写 `0.10` 到 `1.00` 秒（步进 `0.01`），不接受空字符串；自动模式、`null` 或缺少字段都保持旧的自动节奏。设置按商品保存，切换商品或重新载入不会串值。关闭语音时控件禁用，静音成片仍走原有时间轴。

手动值只用于相邻句子之间的空白。每句的口播 PCM 直接放在原时间轴上，句槽按 30 fps 向上取整，因此实测停顿满足“请求值 ≤ 实测值 ≤ 请求值 + 1/30 秒”（允许极小浮点误差）。最后一句继续使用原有尾垫，不会因为手动值在片尾增加额外长停顿；单句也不会改变时长。显式分支对当前切片用 `tpad=stop_mode=clone` 补齐 1–3 帧余量（不另切短尾片），避免旧的 ≤3 帧丢弃规则吞掉手动停顿。

设置层严格拒绝布尔值、字符串、数组、对象、NaN、无穷和越界数字，不做夹紧。渲染报告在启用语音时记录 `sentence_gap_seconds` 和每个相邻句子的 `sentence_pauses.values`；验证器对旧任务继续使用原来的 `0.05..0.40` 秒门，只有带显式参数的报告进入新的请求值区间门。原 PCM、首尾、EOS、删末句和字幕/时间轴校验保持不变。

该功能只证明提供给渲染器的 PCM 样本未被裁切，并不诊断生成端的吞字、重叠字或串音色问题。

本轮未运行真实浏览器、Windows 端、FDK 完整编码链或生产服务；原生字幕 drawtext 探针因当前机器缺少 `drawtext` 而阻断，字幕只核对了字幕文件生成和命令时间轴。真实模型、部署和上线行为均未验。
